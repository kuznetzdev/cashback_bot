# Обзор продукта

## Кратко

Cashback Analyzer — это platform-core продукт для управления банковскими cashback-предложениями.
Он помогает пользователю собрать данные по картам и банкам в одном месте, проверить их, отредактировать и быстро получить практический ответ на вопрос: какой картой выгоднее платить в конкретной категории.

Текущий core не привязан к одному каналу доставки.
Поверх него сейчас работают два внешних интерфейса:

- web-приложение на `FastAPI`, которое является основной платформенной поверхностью
- Telegram-бот на `aiogram`, который выступает как быстрый operational adapter

## Продуктовая задача

Проблема пользователя не в отсутствии cashback как такового, а в том, что выгодные предложения:

- распределены по разным банковским приложениям
- меняются регулярно
- описаны по-разному
- плохо сопоставимы в момент принятия решения

Цель продукта — сократить этот когнитивный и операционный разрыв.

## Что продукт представляет собой сейчас

На текущем этапе это не бухгалтерия и не менеджер расходов.
Это decision-support инструмент для бытового выбора карты под категорию или сценарий покупки.

Система уже умеет:

- хранить банки и cashback-категории пользователя
- принимать данные вручную, по шаблону и через OCR
- нормализовать категории и проценты
- показывать preview перед сохранением
- редактировать уже сохранённые банки
- строить рейтинг по категориям и общий рейтинг
- хранить историю действий
- управлять языком и reminders
- работать через local web auth и linked Telegram identity
- запускать reminder scheduler на уровне runtime, а не внутри Telegram polling lifecycle

Система сознательно не делает:

- учёт транзакций
- расчёт фактически начисленного cashback
- бюджетирование и PFM-функции
- банковскую синхронизацию по API

## Текущий product baseline

### 1. Ввод данных

Пользователь может создать или обновить банк тремя путями:

- ручной ввод строк вида `АЗС 5%`
- загрузка изображения с cashback-категориями
- шаблонный draft с последующей правкой

Во всех вариантах система переводит ввод в единый draft, показывает preview и требует явного подтверждения перед сохранением.

### 2. Проверка и редактирование

Preview — центральный рабочий экран текущего продукта. Через него пользователь:

- видит распознанные категории
- исправляет ошибки OCR или ручного ввода
- меняет названия категорий и проценты
- добавляет и удаляет строки
- сохраняет обновлённый банк целиком

### 3. Использование данных

После сохранения пользователь может:

- открыть список своих банков
- посмотреть детали конкретного банка
- отредактировать или удалить сохранённый банк
- открыть общий рейтинг
- открыть лидеров по конкретной категории
- посмотреть историю последних действий

### 4. Каналы доступа

#### Web

Web — основной платформенный интерфейс. Он уже поддерживает:

- локальную регистрацию
- локальный вход
- Telegram link/unlink для внешней identity
- screen-driven workflow поверх общего application core

#### Telegram

Telegram сейчас не является каноническим центром бизнес-логики и identity-модели.
Это вторичный delivery adapter, который:

- аутентифицирует пользователя через external identity `provider="telegram"`
- переводит команды, callbacks, текст и фото в общий `UserCommand`
- рендерит общий `Screen` и inline actions

Практически это означает, что бот уже представляет собой не «сам продукт», а быстрый интерфейс к общему cashback-core.

## Почему архитектура стала web-first

Переход к web-first связан не с дизайном интерфейса, а с моделью платформы:

- пользователь теперь существует как platform account, а не как Telegram-centric запись
- local credentials и external identities разведены
- Telegram можно связывать и отвязывать как один из identity providers
- общий workflow переиспользуется между web и Telegram

Важно:

- архитектурно продукт уже web-first
- code defaults в `Settings` и `.env.example` теперь совпадают с web-first local mode
- Telegram features включаются явно через `APP_ENABLE_TELEGRAM`, `WEB_ENABLE_TELEGRAM_AUTH` и `REMINDER_DELIVERY_PROVIDER`
- web-only mode остаётся first-class non-Telegram operating mode

## UX-принципы текущего продукта

### Быстрый first value

Пользователь должен быстро пройти путь:

1. добавить или импортировать данные
2. проверить их на preview
3. сохранить банк
4. сразу получить полезный экран: детали банка или рейтинг

### Editing-first

OCR и parsing не считаются источником истины сами по себе.
Система строится вокруг обязательной возможности проверить и поправить результат.

### Никаких silent dead ends

Любой пользовательский ввод должен приводить к следующему экрану, статусу или явной ошибке.
Незавершённый draft нельзя молча потерять при навигации.

### Минимум трения в момент решения

Главный рабочий вопрос продукта звучит так:

> Чем платить сейчас?

Поэтому ranking и best-category flows важнее, чем сложные справочники и управленческие таблицы.

## Целевая аудитория

Основной сегмент:

- пользователи с 2+ картами
- те, кто уже интересуется cashback и акциями
- те, кто готов раз в период обновлять категории, чтобы потом быстро пользоваться результатом

Вторичные сегменты:

- digital-first пользователи, которым нужен мобильный доступ
- занятые пользователи, которым важна скорость ответа
- пользователи, у которых Telegram удобен как быстрый канал, а web — как основной рабочий интерфейс

## Ограничения текущей версии

На текущем baseline продукт ещё не учитывает:

- лимиты cashback на уровне расчётов рейтинга
- сроки действия категорий как обязательный фактор выбора
- card-level metadata внутри одного банка
- историю по месяцам как отдельный аналитический слой
- автообновление офферов из внешних источников

Эти ограничения осознанны: сначала зафиксирован надёжный core для ввода, проверки, хранения и базового выбора.

## Куда продукт можно двигать дальше

### Ближайший прагматичный слой

- card-level сущности вместо bank-only модели
- лимиты и сроки действия категорий
- пометка свежести данных
- более точный ranking с учётом ограничений

### Следующий продуктовый слой

- месячные snapshots категорий
- richer desktop analytics
- bulk editing для power users
- лучшие подсказки по «что пора обновить»

### Канальный слой

- Telegram как быстрый action surface для повседневного использования
- web как основной интерфейс настройки, истории и аналитики
- при необходимости Telegram Mini App для richer mobile UX без возврата к telegram-centric core

## Итог

Сейчас Cashback Analyzer — это уже не просто Telegram-бот с OCR.
Это platform-core система для управления cashback-предложениями, где web стал основной платформенной моделью, Telegram остался быстрым прикладным интерфейсом, а reminder scheduling принадлежит application runtime, а не bot lifecycle.
